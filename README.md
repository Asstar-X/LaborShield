## 为什么做这个项目？

在涉案金额从数千元到数万元的劳动争议中（违法辞退、欠薪、未休年假、加班费差额），普通劳动者常常陷入困境：
1. **请律师成本倒挂**：基础律师费三五千起步，或者要求 20%~30% 风险提成。涉案标的额较小时，请律师不划算，放弃维权又心有不甘。
2. **自己去立案处处碰壁**：
   - **金额算错**：社平工资 3 倍封顶、12 年工龄上限、离职当月年假按日历折算且必须向下取整、计薪天数 21.75 天换算……手工算极易出错。
   - **诉求排他冲突**：把“2N（违法解除赔偿金）”与“+1（代通知金）”混在一起要，或者把“原告/被告”等法院词汇写进仲裁申请书，直接被立案庭退回补正。
   - **格式不规范**：各地人社局推行“要素式审判”，缺少 18 项要素表或标准证据目录，立案窗口无法快速受理。
3. **大模型不能拿来算钱**：直接用 ChatGPT 等通用对话大模型，极易产生浮点算术幻觉、胡诌法条，甚至将公司单方开具的违纪通知当成客观事实引用。法律文书差一分钱，立案庭都会要求退回修改。
4. **不懂程序法，被公司恶意拖垮**：很多用人单位利用员工耗不起时间的弱点，一审、二审打满，拖延一年以上。根据《劳动争议调解仲裁法》第 47 条，将拖欠工资、未休年假等单项金额拆分到当地“月最低工资 × 12”以内，可以争取**一裁终局**（用人单位裁决后无权向法院起诉拖延时间，劳动者享有 15 日起诉权）。

**LaborShield 的原则**：**AI 负责梳理事实与交互引导，所有金额精算、公文格式渲染和合规检查全部交由本地确定性的 Python 脚本执行**。

## 一、 用户全流程指引（从立案到庭审六步闭环）

从劳动争议发生到立案开庭，用户通常经历以下 6 个步骤：

```
用户维权生命周期（6 步闭环）:
[1. 材料盘点]           [2. 依法精算]           [3. 立案风控]           [4. 文书生成]           [5. 庭审对抗]           [6. 时效跟踪]
 /case-setup   -->        /calc       -->       /audit      -->       /docket     -->      /hearing    -->       /track
放入材料建档案        算清各项法定赔偿        查主体/时效/证据        出标准 Word 六件套       必问答辩与调解策略      监控 15 日起诉红线
```

- **第一步：整理材料与建档（`/case-setup`）**
  把劳动合同、工资流水、离职通知书或微信聊天截图放入 `evidence/` 目录，运行 `/case-setup` 建立基准档案 `01-case-profile.md`。
- **第二步：法律赔偿金确定性理算（`/calc`）**
  算清前 12 个月税前应发均薪，精确核算 2N、N、未休年假、加班费，并按当地最低工资标准自动标记“一裁终局”项。
- **第三步：立案前置三大硬门槛审查（`/audit`）**
  审查主体是否适格（是否存在混同用工）、是否在 1 年仲裁时效内、管辖地是否正确，并对证据链进行三性红黄绿灯诊断。
- **第四步：一键生成立案公文六件套（`/docket`）**
  AI 双 Agent 管道（起草 + 审查）配合本地渲染引擎，输出符合仲裁委标准的 6 份 `.docx` Word 文档，直接打印即可签字递交。
- **第五步：庭审质证对抗与调解底线准备（`/hearing`）**
  生成仲裁员开庭必问 8 问 8 答、HR 常见 8 大抗辩反驳词，以及 A/B/C 三级谈判调解底线；若对裁决不服，15 天内转一审起诉状。
- **第六步：案件全生命周期监控（`/track`）**
  动态监控 5 个工作日立案通知、举证截止日、45 天审限，以及裁决送达后 **15 天起诉生死红线**。

## 二、 六大核心命令详解

| 命令 | 阶段定位 | 用户怎么做 | 命令在后台执行了什么 | 最终交付物 |
| :--- | :--- | :--- | :--- | :--- |

| **`/calc`** | 法定赔偿精算与终局拆分 | 输入 `/calc`（可选模式如 `--mode 2N`） | 调用 `tools/labor_calc.py`（基于 `Decimal` 精算）；计算 3 倍社平封顶与 12 年上限；对照当地年最低工资标准判定第 47 条终局属性 | `dockets/calc_result.json` 及精算清单 |
| **`/audit`** | 门槛风控与证据链诊断 | 输入 `/audit` | 审查立案前置三大关卡（主体资格/1年时效/管辖地）；扫描证据生成连续页码；提供微信记录三连闭环方案与举证倒置清单 | 准入通关报告、证据红黄绿灯表 |
| **`/docket`** | 司法公文六件套渲染 | 输入 `/docket` | Drafter 起草文书，Reviewer 逐字比对事实源防止捏造；调用 `tools/generate_docket_docx.py` 渲染 Word 文档；运行 7 项静态合规拦截 | 6 份 `.docx` Word 文档 + 1 份庭审手册 |
| **`/hearing`** | 庭审质证对抗与调解衔接 | 开庭前输入 `/hearing` | 生成仲裁员必问 8 卡与口述回答；拆解公司 HR 常见 8 大抗辩词；提供三级调解方案；裁决后可一键转一审要素式起诉状 | 庭审质证作战手册、调解方案、一审起诉状 |
| **`/track`** | 案件看板与法定时效预警 | 案件推进中输入 `/track` | 读取并维护 `case_tracker.csv`；根据当前日期计算立案审查（5日）、审限（45+15日）及**裁决送达后 15 日起诉生死红线** | 案件周期看板与倒计时警报 |

### 1. Claude Code (CC) 案例：违法辞退与 2N 公文生成

#### 配置与启动
Claude Code 原生支持斜杠命令。在项目根目录启动即可自动加载：
```bash
cd LaborShield
claude
```
*(若希望全局使用，可将本仓库克隆至 `~/.claude/skills/labor-arbitration`)*

#### 实战场景
> 程序员小张入职 5 年多，月薪 3.2 万元。2026 年 10 月公司 HR 口头通知“因业务架构调整，岗位撤销，明天不用来了，没有赔偿”。小张手头有劳动合同、工资银行流水和解除邮件截图。

#### 交互过程
1. **建档盘点**：小张将合同和流水放入 `evidence/` 目录，在 Claude Code 中输入：
   ```
   /case-setup
   ```
   CC 自动检测并提示个人隐私安全，扫描文件提取出入职日（2021-07-01）、离职日（2026-10-15）、前 12 个月平均工资（32,816.67 元），自动写入 `01-case-profile.md`。

2. **精确算账**：小张输入：
   ```
   /calc --mode 2N --unpaid-wages 12873.56 --untaken-leave-days 4
   ```
   CC 立即调用本地计算器，输出如下明确清单：
   ```
   工龄折算：5 年 3 个月 15 天（折算系数 N = 5.5）
   • 违法解除赔偿金 (2N)：¥360,983.37 (32,816.67 × 5.5 × 2) [非终局项]
   • 10月拖欠劳动报酬   ：¥ 12,873.56 (<= 北京年最低工资 29,040 元) [一裁终局项]
   • 未休年假工资差额   ：¥ 12,070.50 (<= 北京年最低工资 29,040 元) [一裁终局项]
   总请求金额：¥385,927.43
   ```
   *（提示：欠薪与年假已作为独立项触发一裁终局，用人单位对该部分无权向法院起诉拖延）*

3. **生成公文**：小张输入：
   ```
   /docket
   ```
   CC 启动起草与审查双 Agent，调用本地排版工具输出 `01~06` 完整的 Word 六件套公文，并通过 7 项合规检查。小张直接打开 Word 打印即可送交仲裁委立案。

### 2. Google Antigravity (Agy) 案例：强制降薪调岗与被迫解除 (N)

#### 配置与启动
Antigravity 原生支持 `.agents/skills/` 规范。在 Antigravity 中直接打开本目录即可自动加载 `arbitration-assistant` 技能。
*(或全局安装：`mkdir -p ~/.gemini/config/skills && git clone <repo> ~/.gemini/config/skills/labor-arbitration`)*

#### 实战场景
> 运营小李被公司强制单方降薪 30% 并要求调岗至异地办公，小李明确不同意，公司威胁“不同意就按旷工开除”。小李想被迫解除劳动合同并索要经济补偿金（N）。

#### 交互过程
小李在 Antigravity 聊天框直接以自然语言提问：
> **小李**：“公司强行下发通知给我降薪 30%，还要求我下周去异地分公司报到，我不同意他们就说按旷工开除。帮我评估一下维权方案，能要到补偿金吗？”

**Antigravity (Agy) 自动激活 `arbitration-assistant` 技能执行响应**：
1. **法理定性与风险提示**：
   - Agy 读取法规库（`02-statutory-rules.md`），明确指出：用人单位单方降薪调岗属于“未按照劳动合同约定提供劳动条件和足额支付报酬”，完全符合《劳动合同法》第 38 条劳动者被迫解除劳动合同的法定情形。
   - **关键操作指导**：提醒小李**绝不能在离职审批表上勾选‘个人原因离职’**，必须通过中国邮政 EMS 寄送《被迫解除劳动合同通知书》，在快递面单和正文中明确写明依据《劳动合同法》第 38 条第一款解除。
2. **调取工具核算**：
   - 自动执行 `python3 tools/labor_calc.py --mode FORCED_N ...`，精确核算工作年限对应的 N 经济补偿金及违法降薪期间的工资差额。
3. **微信与邮件闭环补强**：
   - 指导小李依照“微信三连闭环法”，对 HR 主管发送固定格式的异议回复并截图留证。

### 3. OpenAI Codex 案例：裁决后 15 天起诉红线与一审诉讼衔接

#### 配置与启动
Codex CLI 兼容标准 Agent Skills：
```bash
# 全局加载技能
mkdir -p ~/.codex/skills
git clone https://github.com/<your-username>/LaborShield.git ~/.codex/skills/labor-arbitration
```

#### 实战场景
> 研发老王刚拿到仲裁裁决书，仲裁委支持了 18 万元赔偿金，但因打卡记录不完整驳回了 4 万元周末加班费。公司放话称“要上诉到底打一审二审拖死你”。老王不知该如何应对。

#### 交互过程
老王在终端向 Codex 提问：
> **老王**：“我今天收到仲裁裁决书了，赔偿金支持了，但加班费被驳回了。公司说要上诉到底。这笔赔偿金能马上拿到吗？被驳回的加班费我还能要回来吗？”

**Codex 自动执行工作流**：
1. **拆解裁决效力（戳穿用人单位拖延恐吓）**：
   - Codex 审查各项性质：若赔偿金中包含一裁终局项目（如低于 12 个月最低工资的单项），该部分裁决即告生效，用人单位无权向基层法院起诉；公司声称的“全面上诉拖延”在法律程序上不成立。
2. **预警 15 天生死红线**：
   - 激活 `/track` 规则：提醒老王**自收到裁决书之日起只有 15 天法定起诉期**。如果想追回被驳回的 4 万元加班费，必须在 15 天内向基层人民法院提起诉讼；一旦超期未起诉，仲裁裁决即终局生效，丧失法院起诉权。
3. **一键生成起诉状**：
   - 激活 `/hearing` 的 Mode C，调用模板直接生成符合最高人民法院 2024 最新标准的《劳动争议一审要素式起诉状（加班费追索专项）》，帮助老王在 15 天红线内无缝衔接法院立案。

## 四、 纯命令行独立运行（无需 AI）

如果你不需要 AI 对话引导，只是想找一个**准确无误的计算器**或**公文生成脚本**，所有 Python 工具均可独立运行：

### 1. 赔偿金确定性精算
```bash
python3 tools/labor_calc.py \
  --city 北京 \
  --start-date 2021-07-01 \
  --end-date 2026-10-15 \
  --avg-wage 32816.67 \
  --mode 2N \
  --unpaid-wages 12873.56 \
  --untaken-leave-days 4
```

### 2. 证据目录扫描与自动页码编排
```bash
python3 tools/evidence_timeline.py --evidence-dir evidence --output-manifest
```

### 3. 立案六件套 Word 文档一键渲染
```bash
python3 tools/generate_docket_docx.py \
  dockets/CASE_2026_001_示例科技/draft.json \
  --output-dir dockets/CASE_2026_001_示例科技
```

### 4. 运行 7 项静态合规拦截审查
```bash
python3 tools/verify_docket.py \
  dockets/CASE_2026_001_示例科技 \
  --calc dockets/calc_result.json
```

## 六、 隐私与数据安全

劳动争议材料包含公民高度敏感信息（身份证号码、家庭住址、银行薪资流水、私人聊天记录）。LaborShield 在架构上实行**本地物理级隔离**：

1. **`.gitignore` 默认严密防护**：
   ```gitignore
   evidence/*
   !evidence/README.md
   !evidence/*/.gitkeep

   dockets/*
   !dockets/README.md
   !dockets/CASE_2026_001_示例科技/
   !dockets/calc_result.json
   ```
   存放在 `evidence/` 目录中的真实文件和个人案卷默认被 Git 忽略，绝不会在 `git push` 时上传到公开 GitHub 仓库。
2. **脱敏建档模式**：建档时支持传入 `--redact` 参数，自动将姓名化名化、身份证号隐藏中间 8 位、公司名称替换为代称。
