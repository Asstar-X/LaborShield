# /audit - 前置准入三关与证据链“三性”红黄绿灯诊断工作流

你正在运行 `LaborShield` 的立案前置准入审查与证据链胜诉风险初筛流程。

请严格依照 `.claude/skills/arbitration-assistant/04-evidence-methodology.md` 与 `02-statutory-rules.md` 按顺序执行以下步骤。

---

## Step 1: 读取案件档案与扫描证据库

1. 读取 `.claude/skills/arbitration-assistant/01-case-profile.md` 与 `04-evidence-methodology.md`。
2. 运行证据时间轴与电子数据审计工具：
   ```bash
   python3 tools/evidence_timeline.py --evidence-dir evidence --json
   ```

---

## Step 2: 强制执行立案前置“三大硬性准入关卡” (`Hard Gates`)

在评估具体证据前，必须先输出以下三大硬性关卡的审查表格：

| 准入关卡 | 审查结果 (`PASS` / `FLAG` / `FAIL`) | 事实核验与法律依据说明 |
| :--- | :---: | :--- |
| **Gate 1：主体适格与劳动关系定性关** | `PASS / FLAG / FAIL` | 核验法定退休年龄及养老金状态、被申请人存续状态、是否存在关联混同用工或劳务派遣（若存在，标记追加共同被申请人）。 |
| **Gate 2：仲裁时效与中断审查关** | `PASS / FLAG / FAIL` | 核验各项请求距权利受侵害之日或离职之日是否 ≤ 1 年（《调解仲裁法》第27条），排查时效中断证据。 |
| **Gate 3：管辖权精准锚定关** | `PASS / FLAG / FAIL` | 核验劳动合同履行地（实际工作地）与用人单位注册地，锁定具体区/市劳动人事争议仲裁委员会。 |

> **硬性拦截规则**：若任一关卡为 `FAIL`（如已享受养老金属劳务关系，或超过1年时效且无任何中断事由），必须立即向用户亮出红牌警告并给出替代救济方案，不得盲目鼓励进入 `/docket`。

---

## Step 3: 证据链“三性（真实性、合法性、关联性）”红黄绿灯诊断

围绕本案的每一个待证法律要件（① 劳动关系建立与工龄、② 离职前12个月应得工资标准、③ 违法解除/被迫解除事实、④ 加班与未休年假事实），输出分级诊断：

- **🟢 绿灯铁证（已具备原件/官方凭证，可直接提交）**：列出已齐备的核心书证及其证明力。
- **🟡 黄灯瑕疵（存在质证风险，必须按规范补强）**：
  - 检查微信/钉钉聊天记录是否具备**“实名主页/组织架构页 + 完整连续上下文 + 原始手机终端”三连闭环**；
  - 检查录音证据是否已配备带 **`[MM:SS]` 秒级时间戳** 的《录音文字整理稿》；
  - 检查银行流水是否配套了“个人所得税 App”《收入纳税明细》以还原税前应得工资。
- **🔴 红灯盲区与逻辑冲突（高危败诉点）**：
  - 检查是否存在排他冲突诉求（如同时主张继续履行与2N，或2N叠加+1代通知金）；
  - 检查是否存在劳动者签署“个人原因辞职”等不利自认材料。

---

## Step 4: 生成《举证责任倒置申请与课前补强清单》

1. 明确列出根据《劳动争议调解仲裁法》第六条、第三十九条及《最高法劳动争议解释（一）》第四十四条**应由用人单位负举证责任**的事项（辞退合法性、减少劳动报酬、工龄计算、由单位掌握的原始考勤与两年内工资台账）。
2. 给出用户在递交仲裁申请前需完成的 **1~3 项具体补强动作**（如导出个税 App 截图、补截对方微信号主页、整理录音文字稿）。
3. 更新 `case_tracker.csv` 中对应案件状态为 `audited`，询问用户是否进入 `/docket` 生成立案全套文书。
